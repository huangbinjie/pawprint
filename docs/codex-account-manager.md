# Codex Account Manager (macOS)

Pawprint manages Codex's user configuration independently of Pawprint's own AI features. Right-click the desktop pet, then **Codex 账号与 Provider**. The native menu marks the configured selection. **添加 / 管理 Provider…** opens Preferences, where you can add a name, Base URL, API key and model, refresh status, select a provider, or delete a provider, including the selected one. Deletion asks for confirmation; when the selected provider is deleted, ChatGPT defaults are restored before its credential is removed. If configuration conflicts prevent restoring ChatGPT, deletion is refused. Double-click still returns to a Codex chat.

You can switch defaults while Codex is running. Start a new chat afterward and confirm its Provider and model. Pawprint does not terminate processes, restart Codex, or claim that an existing chat or the Desktop account indicator has changed. A client that passes explicit cached model/provider overrides can override the new file defaults.

After switching, Pawprint reads back the configuration before requesting a refresh of the client's bottom-left Provider label. It uses the observed local Desktop coordination broadcast `query-cache-invalidate` (version 0), scoped to `['user-saved-config', 'local', null]`. This cache has a five-minute freshness period in the inspected client; that is not a periodic refresh timer. The existing client menu supports showing the account name, plan and provider together when account information is available. Pawprint does not change login information or manufacture the account name.

This refresh is best effort and uses an internal interface. A successful socket write means **refresh requested**, not **indicator updated** or **API connection tested**: there is no display acknowledgement. Missing, incompatible or unresponsive IPC produces an explicit fallback message; a notification failure does not undo a successful configuration change. Clicking the selected connection again retries the refresh. A readback mismatch suppresses the notification and reports that the selection could not be confirmed. The adapter connects only to an owned, non-symlink local socket, has a 1.5-second connection/handshake limit, and sends no chat, login, logout or approval actions. It does not invalidate remote-host or unrelated caches. Existing chats keep their original provider.

Switching from either the native pet menu or the connection page sends a silent system notification with the selected connection name. No custom desktop overlay is shown. macOS can store the notification only in Notification Center when banners are disabled; select a banner/alert style for Pawprint in System Settings → Notifications to show it immediately. The connection page explains this and offers **Open notification settings**, which opens the Pawprint-specific macOS settings page without changing system permissions or provider configuration. The native provider menu has the same shortcut. The notification distinguishes an unconfirmed indicator refresh from a failed configuration switch; clicking it opens Codex Assistant. Existing inline results remain available. Notification delivery is controlled by the operating system and does not change the switch outcome.

## Configuration conflict recovery

The connection page identifies changed fields (default selection, connection names, Base URL, API protocol or authentication), without exposing their values. Ordinary switches still refuse external edits. **Resolve configuration conflict** opens an explicit confirmation to back up the current TOML, regenerate only Pawprint-managed connection definitions from saved metadata and restore the saved ChatGPT default. Unrelated settings and external provider definitions outside the managed block remain intact; login credentials are not changed. A review fingerprint covers both the full configuration and the saved connection metadata. Any intervening change invalidates the confirmation. Profiles, forced API login or ambiguous changes that cannot be safely isolated remain manual; the UI does not offer automatic recovery for those cases.

## Recent chat providers

The connection page includes a read-only list of up to eight recent chat providers from local metadata. Provider and model come from each chat’s own record, independent of the current default. Explicit names/index titles are used; prompt text, raw prompt-derived titles and local project paths are not displayed. Untitled chats stay untitled; absent providers remain unconfirmed. Archived, subagent and explicitly remote/cloud records are excluded. Reading the list creates no chat and sends no model request. In an isolated real app-server probe, `thread/start` returned the new provider before any message, but that empty thread was not yet present in SQLite. Empty chats can therefore be absent from this list; the list does not promise to discover every unsaved Desktop draft. A recorded provider does not certify API connectivity or a completed inference request. **Refresh status** updates this list.

## Preserve ChatGPT identity across client restarts

When an existing file-based ChatGPT login is recognized, tracked Pawprint connections are upgraded after a configuration backup to use `requires_openai_auth = true` and a private loopback inference bridge. This preserves the client's ChatGPT authentication mode instead of presenting the connection as an account without ChatGPT identity. The Provider ID/name stays the same. The first upgrade needs one client restart to rebuild its initial identity state; subsequent Codex restarts can load the saved ChatGPT identity while the selected third-party connection remains configured.

**Keep Pawprint running while using these third-party connections.** The bridge starts with Pawprint and retains its address across restarts. It listens only on `127.0.0.1`, uses a private capability route, rejects browser-origin requests, forwards only Responses/compaction requests, and replaces incoming authentication with that Provider’s Keychain API key. ChatGPT bearer credentials, account headers and cookies are not forwarded to the third party or written to logs/configuration. Redirects are not followed. An unavailable/occupied bridge does not silently send ChatGPT credentials to the Provider's remote URL. Returning to OpenAI remains available even if the bridge cannot start.

The client's **Usage** menu represents the ChatGPT account, not a third-party API balance. Pawprint's per-provider usage stays separate. Backend tests verify cold-start `chatgpt` identity/plan, the account rate-limits API, model listing, mock Responses routing through the bridge, a combined Pawprint/backend restart, and return to OpenAI. This is not a claim that every feature is available for every provider/model or that Desktop pixels were automatically verified. Cloud/voice/model capabilities still depend on the client, account entitlements and Provider compatibility.

The upgrade preserves existing login data and refuses external configuration conflicts. Existing API-only connections without a recognized file-based ChatGPT login retain the direct Keychain-command mode. Automatic discovery of ChatGPT credentials stored exclusively in the system credential store is not implemented in this version.

## Credentials and configuration

- API keys are generic-password entries in the macOS login Keychain, under service `studio.binmax.pawprint.codex-provider`. Saving uses stdin, not command-line arguments. Keys are never returned to the renderer or written to TOML, Pawprint's metadata or backups. macOS may ask to unlock or authorize Keychain access.
- In direct/API-only mode, Codex uses `[model_providers.<id>.auth]` with `/usr/bin/security find-generic-password ... -w`. In identity-preserving mode, Pawprint reads the Provider key from Keychain for the loopback bridge and Codex uses its saved ChatGPT identity locally. No replacement of `auth.json` or logout/login is needed.
- Actual configuration home is `CODEX_HOME`, when inherited by Pawprint, otherwise `~/.codex`. The usage-import directory selected in Pawprint does **not** change the account manager's target. Inspect the displayed configuration path before switching.
- Only top-level `model` and `model_provider` plus a marked Pawprint provider block are changed. Definitions for all saved Providers remain in that block when switching or restoring ChatGPT so existing custom-provider chats can still resolve their original Provider. Deleting a Provider removes its Keychain credential and can prevent those old chats from making further requests. Other fields, comments, project settings and provider definitions are retained. Parsed TOML is compared before and after to reject ambiguous modifications.
- Each switch creates a private (0600) full TOML backup in `<Codex home>/pawprint-account-backups/`. Existing sensitive values in a user's original configuration are present in that full backup; Pawprint does not add its API keys to it.
- The OpenAI model/provider lines saved before the latest switch away are restored when selecting **当前 ChatGPT / OpenAI 登录**. Pawprint leaves `auth.json` and Codex's own Keychain entries untouched. This label refers to the existing OpenAI login, and does not certify that the user has a valid ChatGPT subscription or token.
- A lock prevents concurrent Pawprint switches. A final config recheck and atomic replacement reduce external-write races. Other tools do not honor Pawprint's lock; no filesystem API can guarantee a compare-and-swap against an uncooperative writer. An externally changed Provider selection or connection definition causes a refusal instead of an overwrite. Normal changes to the root model from Codex’s model picker and equivalent TOML formatting are allowed; the latest model selected while OpenAI is active becomes the return model for the next round trip. Switching outcomes appear beside the chosen connection. Changes to unrelated fields are retained.
- A private transaction record resolves interrupted writes on the next load. If a process is killed mid-switch, verify the configuration and backup before removing a leftover `.pawprint-account-lock` directory. If model fields or the marked block were externally changed, reconcile those fields with the backup before retrying; reviewed recovery is available only when the configuration can be safely isolated; there is no unreviewed force-overwrite action.

## Compatibility and limits

The gateway must implement the **Responses API**, including the streaming/tool behavior needed by Codex. An “OpenAI-compatible” service with only Chat Completions is insufficient. There is no remote provider connectivity test, model discovery UI, or automatic protocol translation in this version.

Requires a Codex version with command-backed provider authentication. On 2026-10-15, the installed `codex-cli 0.162.0-alpha.17.2` was tested using one continuously running app-server, an isolated private Codex home, real temporary Keychain entries and a loopback mock Responses server. The test switched OpenAI → Provider A → Provider B → OpenAI without restarting. Fresh threads sent requests with the corresponding Provider A/B model and dummy bearer token and completed streamed mock replies. After restoring OpenAI, an existing Provider A thread also completed another request using A, confirming retained provider definitions. A fresh OpenAI thread using the user's authorized existing ChatGPT login replied `PAWPRINT_CHATGPT_OK`. The original user configuration and login file were not changed; the temporary login copy and dummy Keychain entries were deleted afterward.

This verifies live backend defaults, credential routing and return to ChatGPT, **not the Desktop frontend**. Subsequent local user testing confirmed that the account-menu Provider indicator updates after the targeted cache refresh. That observation does not add a programmatic display acknowledgement or verify every Desktop-created thread’s routing. Computer Use explicitly denied access to `com.openai.codex`, so the client’s **bottom-left** account/Provider indicator and Desktop-created thread overrides remain unverified. No alternate UI automation was used to bypass that restriction. The UI therefore reports “defaults updated,” asks the user to confirm Provider/model in a new chat, and does not claim a verified client-wide switch or indicator refresh.

Multiple ChatGPT login identities are not implemented. Existing custom default providers, active `profile`, forced API login, malformed TOML, symlink configuration files and ambiguous model-line syntax are refused rather than silently overridden. Model-specific user options remain intact and can be incompatible with a third-party model. macOS is the only supported platform; Windows shows an unavailable manager.

## Provider labels in chat titles

Enabled by default under **Provider 标题标注**. Hook events trigger a scan, with a 15-second fallback poll when a turn does not invoke hooks. Pawprint reads local per-thread `model_provider` plus explicit title metadata, then verifies the provider through `thread/read` before using the supported `thread/name/set` interface to add `[Provider name] `. It does not derive providers from current defaults or rewrite Codex's SQLite database directly. No model request, prompt, approval, or frontend injection is used for naming.

OpenAI chats, archived chats, subagents, unknown providers and threads without explicit titles are skipped. Provider names come from saved account metadata, then configuration, then the recorded provider ID. Remote-only threads cannot be labelled without authoritative local metadata and are left unchanged. Each scan considers the 64 most recently updated eligible local chats. Existing non-OpenAI chat titles may be labelled as well as new chats.

Duplicate prefixes are avoided. Custom user prefixes are retained; when the client's automatic title changes, the provider prefix is reapplied. Original titles and applied prefixes are recorded in private `codex-provider-titles.json` for recovery. Disabling stops future changes and leaves existing prefixes in place. The Desktop sidebar may require a list refresh or reopening to show externally updated names; GUI refresh remains unverified because Computer Use cannot access Codex.

Verified with isolated real Codex app-server metadata: Provider A/B titles received their correct prefix, an existing `[Bug]` prefix remained, OpenAI's title stayed unchanged, and a second scan made no duplicate edits.

## Codex Assistant page and usage

The sidebar's **Codex 助手** page groups connections, chat/reminder controls, usage/limits and advanced settings. New Provider fields are in a modal; local configuration, backup and record paths are collapsed in Advanced. Product examples use generic placeholders and do not include the author's account/provider names, URLs or local paths. Saved connection names appear only as the user's actual data.

**用量与额度** aggregates the last seven days of available local token records by their recorded Provider, including input, cached input and output. It does not reassign old usage to the currently selected default. Explicit Provider changes in turn/context or applied settings records are honored. A parser cache revision invalidates older per-file caches so these changes are recalculated.

Reference prices remain separate from real bills. For display-only reference costs, each recorded request model is matched against the existing model-prices JSON (with the bundled offline table as fallback). Ordinary input, cached input, cache writes, output, context tiers and service tiers use the existing pricing rules per request. Provider-specific prices take precedence; otherwise a canonical or unambiguous model match supplies a **reference**, not a claimed gateway rate. Unknown or conflicting model matches remain **未定价**. Partial reference totals are labelled partial. This additional reference value does not change reward/accounting costs. Actual gateway balances, subscription plans and invoices require the provider dashboard or a separate supported billing API. Remote-only records absent from the local data are not counted, and old subscription snapshots are not the balance of the selected third-party connection. This page does not change the pet reward rules.

Usage cards in both Codex Assistant and Usage & Wallet resolve recorded Provider IDs to the saved connection names. A name-only history is retained when deleting a connection so older records can still be labelled; API keys are removed as before. When a managed ID has no recoverable name, the UI shows a generic custom-provider label with a short identifier instead of the full internal ID. Usage & Wallet model cards also use the display-only reference cost fields and their matching unpriced count.
