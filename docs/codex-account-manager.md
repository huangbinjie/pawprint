# Codex Account Manager (macOS)

Pawprint manages Codex's user configuration independently of Pawprint's own AI features. Right-click the desktop pet, then **Codex 账号与 Provider**. The native menu marks the configured selection. **添加 / 管理 Provider…** opens Preferences, where you can add a name, Base URL, API key and model, refresh status, select a provider, or delete a provider, including the selected one. Deletion asks for confirmation; when the selected provider is deleted, ChatGPT defaults are restored before its credential is removed. If configuration conflicts prevent restoring ChatGPT, deletion is refused. Double-click still returns to a Codex chat.

You can switch defaults while Codex is running. Start a new chat afterward and confirm its Provider and model. Pawprint does not terminate processes, restart Codex, or claim that an existing chat or the Desktop account indicator has changed. A client that passes explicit cached model/provider overrides can override the new file defaults.

After switching, Pawprint reads back the configuration before requesting a refresh of the client's bottom-left Provider label and local root-config capability queries. It uses the observed local Desktop coordination broadcast `query-cache-invalidate` (version 0), scoped to `['user-saved-config', 'local', null]` and the local root `config/read-response`, `config/layered-response`, and `config/effective` query prefixes. The last prefix also covers the required/fail-closed configuration read used for Dot. These caches have five-minute freshness periods in the inspected client; these are not periodic refresh timers. The existing client menu supports showing the account name, plan and provider together when account information is available. Pawprint does not change login information or manufacture the account name.

This refresh is best effort and uses an internal interface. A successful socket write means **refresh requested**, not **indicator updated** or **API connection tested**: there is no display acknowledgement. Missing, incompatible or unresponsive IPC produces an explicit fallback message; a notification failure does not undo a successful configuration change. Clicking the selected connection again retries the refresh. A readback mismatch suppresses the notification and reports that the selection could not be confirmed. The adapter connects only to an owned, non-symlink local socket, has a 1.5-second connection/handshake limit, and sends no chat, login, logout or approval actions. It does not invalidate remote-host or unrelated caches. Existing chats keep their original provider.

Switching from either the native pet menu or the connection page sends a silent system notification with the selected connection name. No custom desktop overlay is shown. macOS can store the notification only in Notification Center when banners are disabled; select a banner/alert style for Pawprint in System Settings → Notifications to show it immediately. The connection page explains this and offers **Open notification settings**, which opens the Pawprint-specific macOS settings page without changing system permissions or provider configuration. The native provider menu has the same shortcut. The notification distinguishes an unconfirmed indicator refresh from a failed configuration switch; clicking it opens Codex Assistant. Existing inline results remain available. Notification delivery is controlled by the operating system and does not change the switch outcome.

When menu-bar text is enabled, Pawprint shows the selected third-party Provider name instead of an unknown or unrelated ChatGPT quota. Selecting ChatGPT / OpenAI restores the local account-quota snapshot display. The tray updates as soon as the saved selection passes readback, before waiting for the Codex client refresh or the 15-second quota scan. Failed switches keep the previous label. The selected service is restored after Pawprint restarts. No third-party balance or quota API is queried. Empty quota events from bridge-observed third-party chats are excluded from official quota selection; official empty snapshots, stale markers and reset times retain their existing meaning.

## Configuration conflict recovery

The connection page identifies changed fields (default selection, connection names, Base URL, API protocol or authentication), without exposing their values. Ordinary switches still refuse external edits. **Resolve configuration conflict** opens an explicit confirmation to back up the current TOML, regenerate only Pawprint-managed connection definitions from saved metadata and restore the saved ChatGPT default. Unrelated settings and external provider definitions outside the managed block remain intact; login credentials are not changed. A review fingerprint covers both the full configuration and the saved connection metadata. Any intervening change invalidates the confirmation. Profiles, forced API login or ambiguous changes that cannot be safely isolated remain manual; the UI does not offer automatic recovery for those cases.

## Recent chat providers

The connection page includes a read-only list of up to eight recent chat providers from local metadata. Provider and model come from each chat’s own record, independent of the current default. Explicit names/index titles are used; prompt text, raw prompt-derived titles and local project paths are not displayed. Untitled chats stay untitled; absent providers remain unconfirmed. Archived, subagent and explicitly remote/cloud records are excluded. Reading the list creates no chat and sends no model request. In an isolated real app-server probe, `thread/start` returned the new provider before any message, but that empty thread was not yet present in SQLite. Empty chats can therefore be absent from this list; the list does not promise to discover every unsaved Desktop draft. A recorded provider does not certify API connectivity or a completed inference request. **Refresh status** updates this list.

### Existing-chat switching capability probe

`node scripts/test-codex-thread-switch.mjs` uses two mock clients sharing one temporary app-server daemon and a loopback Responses service. It does not open Desktop, copy login credentials, or modify the user's configuration. On 2026-10-21, `codex-cli 0.163.0-alpha.11` showed:

- Changing defaults leaves an already loaded chat on its original Provider. A second client's `thread/resume` with another Provider/model is accepted but its overrides are ignored; the server reports the original effective Provider/model.
- Unsubscribing only the second client is insufficient while the first client remains subscribed. After both clients unsubscribe, resuming the same chat with Provider B makes the next request reach B and retains its history and ID.
- A client can still pass a stale `model` override on `turn/start`: the request reaches B with the old model name. Model changes and Provider changes must be verified separately.

These are backend capability checks, not Desktop integration acceptance. A reliable follow-default switch would need cooperation from the client that owns the open chat: wait for a safe turn boundary, release all subscriptions, resume with the intended Provider/model, and reconcile cached model overrides. Pawprint has no verified integration for that lifecycle yet. No follow-default toggle is exposed, and a successful global config switch or a title prefix must not be presented as proof that an existing chat was rerouted. Any future cross-provider migration must explicitly explain that subsequent requests can include existing conversation history at the newly selected service.

## Keep Dot and account services

Third-party connections always keep the built-in OpenAI Provider identity and use the private loopback inference bridge. There is no mode selector, preservation switch or `tbo_available` entitlement detector. The selected upstream name/model remains visible in Pawprint under **Current service**; Codex may hide it in its ChatGPT account menu. Actual availability of Dot and other account services still depends on the account and client.

Model forwarding is chosen automatically by exact model-ID membership in a native `model/list` snapshot. The read-only helper queries the same Codex configuration home, including pagination and hidden-model filtering; it sends no inference or thread requests. It does not inspect model-name prefixes, use a hardcoded model list, or infer upstream service support. It is a separate metadata process, so its list can differ from an already-open Desktop window retaining an older catalog. Successful snapshots are reused for up to one minute; **Refresh status** requests a fresh read.

When the configured model appears in that list, the bridge preserves the native picker's requested model, including title-generation and compaction models. When it is absent, only the request's `model` field is replaced with the connection's configured model. An unavailable, malformed or incomplete list is an unknown result, not proof of absence: the picker remains active and Pawprint displays a retry notice. This adds no switch or saved mode preference. The client catalog is never replaced or reloaded. All other request options remain subject to the service's Responses API compatibility. Route observations record the actual forwarded model; native session/usage metadata may still describe the client's requested model. Selecting **ChatGPT / OpenAI** restores direct official routing and native selection. `node scripts/test-codex-model-routing.mjs` checks a running native backend with dummy credentials and loopback services: GPT picker changes pass through, a newly registered MiMo connection pins chat/title/compaction, and official routing is restored without restarting the backend.

For successful HTTP responses, a separate bounded turn-route map retains only thread ID, turn ID, Provider ID, forwarded model, timestamp and an ambiguity flag. Turn IDs are read from validated native turn metadata; prompts, response contents, account/installation metadata and credentials are not stored. The usage reader matches each metering row to its exact turn, so a rewritten MiMo request is attributed to MiMo while other turns retain their own model and Provider. Conflicting routes within one turn remain unattributed. Attempted destinations used for title labels do not establish usage attribution, and old chats are not relabeled wholesale from the last observed destination. Changed route facts invalidate only the affected session's usage cache. The map retains up to 10,000 turns for 35 days; historical requests without exact turn evidence retain their native metadata.

MiMo API reference fees prefer the Xiaomi API catalog over reseller rates and zero per-token subscription-plan entries. A Token Plan subscription still requires its own quota/billing integration: the API reference fee does not represent the subscription charge, remaining balance or plan entitlement. The token counts continue to come from native metering records and reference fees do not mint extra pet coins.

Selecting **ChatGPT / OpenAI** restores the saved official configuration and existing login. Legacy preservation/mode preferences are removed on save; managed legacy connections migrate to the fixed preservation path at startup when a supported file-based ChatGPT login is available and there is no configuration conflict. Missing login or an unavailable bridge causes an explicit error when selecting a third-party connection instead of silently choosing direct API authentication. Existing external configuration conflicts remain protected. Credential-store-only login discovery is not implemented.

**Keep Pawprint running while using third-party services with the local bridge.** The bridge retains its address across restarts, listens only on `127.0.0.1`, rejects browser-origin requests and removes incoming credentials/account headers before using the selected service's Keychain API key. It forwards only Responses/compaction requests. ChatGPT credentials are not forwarded to the third party or written into config or routing records. Redirects are not followed.

Native ChatGPT-authenticated clients can compress request JSON with Zstd. The bridge decodes Zstd, gzip, deflate and Brotli locally, then forwards plain JSON with the Provider key. Both encoded and decoded request bodies are limited to 32 MiB; invalid or unsupported encodings are rejected before accessing credentials or forwarding. `node scripts/test-codex-bridge-compression.mjs` exercises a real native client with dummy ChatGPT JWTs and local-only account/inference mocks, including its WebSocket-to-HTTP fallback and Zstd request. API-key-only probes do not cover this native compression behavior.

HTTP headers are forwarded by default in both directions. Credentials and client identity headers (including authentication/token/key/cookie fields and account, organization, project, workspace and user identifiers) are removed; the request receives only the selected Provider's Authorization credential. Standard hop-by-hop headers and every header named by `Connection` are removed independently in each direction. Requests regenerate Host and Content-Length and drop the original Content-Encoding and body digests after local decoding/model rewriting. Protocol flags, unknown feature headers, content negotiation, request IDs, model etags and retry/rate-limit hints remain available without individual allowlisting. Responses retain their original encoded byte stream and matching Content-Encoding/Content-Length, bypassing fetch's automatic decompression; streaming is not buffered. Responses drop cookies, credentials and Alt-Svc routing and retain the local no-store cache policy.

### Why connections use the built-in Provider

In the installed ChatGPT/Codex desktop build `26.1016.51333` (`21161`), static application code registers `orbit` with `requiresFirstPartyInference: true`. When the corresponding capability check is active, it requires the effective root `model_provider` to equal `openai` (or be unset), even if a custom Provider has `requires_openai_auth = true`. The Dot navigation component returns no entry when that capability is false. This explains a concrete reason for the missing sidebar entry; notification navigation and existing Dot profiles have separate paths. No application files, entitlement checks or rollout flags are patched by Pawprint.

Selecting a third-party connection backs up configuration, keeps the selected service in Pawprint, and writes `model_provider = "openai"` plus `openai_base_url` pointing at that service's existing private loopback bridge route. The ordinary custom Provider definitions remain available for old chats. The bridge continues to strip incoming login/identity headers and uses the selected service's Keychain credential. WebSocket probes receive 426 so the built-in client uses the existing HTTP Responses bridge without repeated reconnect attempts. Returning to ChatGPT restores the original OpenAI model and any original `openai_base_url`. Use a new chat after switching defaults. Active chats are not migrated or interrupted. Existing custom-Provider chats retain their Provider IDs. Chats created in compatibility mode have the shared `openai` ID, so after a later restart/resume they can use a newly configured OpenAI base URL or the restored official endpoint, including sending prior history to that service. The preservation notes disclose this tradeoff; it is not the proposed optional live thread-migration feature.

The Codex account menu and saved chat metadata can identify new compatible chats as OpenAI. Pawprint still displays its selected upstream service. For title labels and recent-chat sources, the bridge can retain up to 512 dispatched-request observations (thread ID from `thread-id`, Provider ID, model, timestamp). It stores no prompt, response body, credential, identity header or capability URL. Native OpenAI-labelled chats are eligible for a third-party title prefix only with a matching route observation, not merely because that Provider is currently selected. These labels describe the last attempted destination, including failed requests, not a success/billing record or a guarantee about a future request; disabling title labels retains existing prefixes. Native usage metadata may still attribute these chats to OpenAI; provider billing remains authoritative.

`node scripts/test-codex-dot-mode.mjs` verifies the built-in Provider identity and streamed model request through the actual bridge using an isolated real app-server, temporary config, and dummy API credentials. It checks that the configured ChatGPT login fixture is untouched by the mode change and that third-party requests contain no incoming login token. The inference fixture uses API authentication because fake ChatGPT JWTs cannot pass the client's workspace routing discovery. This is transport/configuration evidence, not verification of a real account's Dot entitlement or the sidebar pixels. Native UI inspection of this app is denied by Computer Use; visible recovery still requires user acceptance after restart. Internal cache broadcasts have no UI acknowledgement, and a missing-handler log from an IPC peer is not evidence that all client windows failed to refresh.

### ChatGPT quota checks

The desktop client can disable sending for an exhausted ChatGPT subscription before it sends an inference request, including when the selected upstream is third-party. A bridge cannot change a request the client never sends. The preservation notes explain this limitation.

This does not increase ChatGPT quota. Switching to ChatGPT / OpenAI still uses the existing account and its limits; third-party service limits and billing remain with that service.

## Credentials and configuration

- API keys are generic-password entries in the macOS login Keychain, under service `studio.binmax.pawprint.codex-provider`. Saving uses stdin, not command-line arguments. Keys are never returned to the renderer or written to TOML, Pawprint's metadata or backups. macOS may ask to unlock or authorize Keychain access.
- For managed third-party connections, Pawprint reads the Provider key from Keychain for the loopback bridge and Codex uses its saved ChatGPT identity locally. No replacement of `auth.json` or logout/login is needed.
- Actual configuration home is `CODEX_HOME`, when inherited by Pawprint, otherwise `~/.codex`. The usage-import directory selected in Pawprint does **not** change the account manager's target. Inspect the displayed configuration path before switching.
- Only top-level `model`, `model_provider`, and `openai_base_url` plus a marked Pawprint provider block are changed. Definitions for all saved Providers remain in that block when switching or restoring ChatGPT so existing custom-provider chats can still resolve their original Provider. Deleting a Provider removes its Keychain credential and can prevent those old chats from making further requests. Other fields, comments, project settings and provider definitions are retained. Parsed TOML is compared before and after to reject ambiguous modifications.
- Each switch creates a private (0600) full TOML backup in `<Codex home>/pawprint-account-backups/`. Existing sensitive values in a user's original configuration are present in that full backup; Pawprint does not add its API keys to it.
- The OpenAI model/provider lines saved before the latest switch away are restored when selecting **当前 ChatGPT / OpenAI 登录**. Pawprint leaves `auth.json` and Codex's own Keychain entries untouched. This label refers to the existing OpenAI login, and does not certify that the user has a valid ChatGPT subscription or token.
- A lock prevents concurrent Pawprint switches. A final config recheck and atomic replacement reduce external-write races. Other tools do not honor Pawprint's lock; no filesystem API can guarantee a compare-and-swap against an uncooperative writer. An externally changed Provider selection or connection definition causes a refusal instead of an overwrite. Normal changes to the root model from Codex’s model picker and equivalent TOML formatting are allowed; the latest model selected while OpenAI is active becomes the return model for the next round trip. Switching outcomes appear beside the chosen connection. Changes to unrelated fields are retained.
- A private transaction record resolves interrupted writes on the next load. If a process is killed mid-switch, verify the configuration and backup before removing a leftover `.pawprint-account-lock` directory. If model fields or the marked block were externally changed, reconcile those fields with the backup before retrying; reviewed recovery is available only when the configuration can be safely isolated; there is no unreviewed force-overwrite action.

## Compatibility and limits

The gateway must implement the **Responses API**, including the streaming/tool behavior needed by Codex. An “OpenAI-compatible” service with only Chat Completions is insufficient. There is no remote provider connectivity test, model discovery UI, or automatic protocol translation in this version.

Requires a Codex version with command-backed provider authentication. On 2026-10-15, the installed `codex-cli 0.162.0-alpha.17.2` was tested using one continuously running app-server, an isolated private Codex home, real temporary Keychain entries and a loopback mock Responses server. The test switched OpenAI → Provider A → Provider B → OpenAI without restarting. Fresh threads sent requests with the corresponding Provider A/B model and dummy bearer token and completed streamed mock replies. After restoring OpenAI, an existing Provider A thread also completed another request using A, confirming retained provider definitions. A fresh OpenAI thread using the user's authorized existing ChatGPT login replied `PAWPRINT_CHATGPT_OK`. The original user configuration and login file were not changed; the temporary login copy and dummy Keychain entries were deleted afterward.

This verifies live backend defaults, credential routing and return to ChatGPT, **not the Desktop frontend**. Subsequent local user testing confirmed that the account-menu Provider indicator updates after the targeted cache refresh. That observation does not add a programmatic display acknowledgement or verify every Desktop-created thread’s routing. Computer Use explicitly denied access to `com.openai.codex`, so the client’s **bottom-left** account/Provider indicator and Desktop-created thread overrides remain unverified. No alternate UI automation was used to bypass that restriction. The UI therefore reports “defaults updated,” asks the user to confirm Provider/model in a new chat, and does not claim a verified client-wide switch or indicator refresh.

Multiple ChatGPT login identities are not implemented. Existing custom default providers, active `profile`, forced API login, malformed TOML, symlink configuration files and ambiguous model-line syntax are refused rather than silently overridden. Model-specific user options remain intact and can be incompatible with a third-party model. macOS is the only supported platform; Windows shows an unavailable manager.

## Provider labels in chat titles

Enabled by default under **Provider 标题标注**. Request dispatch and explicit title-index changes trigger scans; title-index events are coalesced for 80 ms, with the existing 15-second fallback poll retained. The bridge records the actual destination when sending the request, before response headers or stream completion. An event arriving during a scan queues another scan. Pawprint reads local per-thread `model_provider` plus explicit title metadata, then verifies the provider through `thread/read` before using the supported `thread/name/set` interface to add `[Provider name] `. It does not derive providers from current defaults or rewrite Codex's SQLite database directly. No model request, prompt, approval, or frontend injection is used for naming.

OpenAI chats, archived chats, subagents, unknown providers and threads without explicit titles are skipped. Provider names come from saved account metadata, then configuration, then the recorded provider ID. Remote-only threads cannot be labelled without authoritative local metadata and are left unchanged. Each scan considers the 64 most recently updated eligible local chats. Existing non-OpenAI chat titles may be labelled as well as new chats.

Duplicate prefixes are avoided. Custom user prefixes are retained; when the client's automatic title changes, the provider prefix is reapplied. Original titles and applied prefixes are recorded in private `codex-provider-titles.json` for recovery. Disabling stops future changes and leaves existing prefixes in place. The Desktop sidebar may require a list refresh or reopening to show externally updated names; GUI refresh remains unverified because Computer Use cannot access Codex.

`node scripts/test-codex-title-latency.mjs` uses an isolated real app-server, a temporary login and a loopback provider whose response is held open. It creates a title through `thread/name/set` and checks that the provider prefix is persisted before the provider sends any response headers. This verifies backend timing; it does not measure Desktop sidebar rendering latency.

Verified with isolated real Codex app-server metadata: Provider A/B titles received their correct prefix, an existing `[Bug]` prefix remained, OpenAI's title stayed unchanged, and a second scan made no duplicate edits.

## Codex Assistant page and usage

The sidebar's **Codex 助手** page groups connections, chat/reminder controls, usage/limits and advanced settings. New Provider fields are in a modal; local configuration, backup and record paths are collapsed in Advanced. Product examples use generic placeholders and do not include the author's account/provider names, URLs or local paths. Saved connection names appear only as the user's actual data.

**用量与额度** aggregates the last seven days of available local token records by their recorded Provider, including input, cached input and output. It does not reassign old usage to the currently selected default. Explicit Provider changes in turn/context or applied settings records are honored. A parser cache revision invalidates older per-file caches so these changes are recalculated.

Reference prices remain separate from real bills. For display-only reference costs, each recorded request model is matched against the existing model-prices JSON (with the bundled offline table as fallback). Ordinary input, cached input, cache writes, output, context tiers and service tiers use the existing pricing rules per request. Provider-specific prices take precedence; otherwise a canonical or unambiguous model match supplies a **reference**, not a claimed gateway rate. Unknown or conflicting model matches remain **未定价**. Partial reference totals are labelled partial. This additional reference value does not change reward/accounting costs. Actual gateway balances, subscription plans and invoices require the provider dashboard or a separate supported billing API. Remote-only records absent from the local data are not counted, and old subscription snapshots are not the balance of the selected third-party connection. This page does not change the pet reward rules.

Usage cards in both Codex Assistant and Usage & Wallet resolve recorded Provider IDs to the saved connection names. A name-only history is retained when deleting a connection so older records can still be labelled; API keys are removed as before. When a managed ID has no recoverable name, the UI shows a generic custom-provider label with a short identifier instead of the full internal ID. Usage & Wallet model cards also use the display-only reference cost fields and their matching unpriced count.
